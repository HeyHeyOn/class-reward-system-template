# CRS 보안 및 성능 패치 결과

2026년 10월 7일 보안·성능 점검 보고서에 따라 수정했다. 대상은 haeon0511 Vercel의 `crs-postgresql` 프로젝트이며, 사용자 입구는 https://crs-postgresql.vercel.app/classes 이다. 기존 Google Sheets 배포와 매점의 학생 번호 조회 정책은 변경하지 않는다.

**현재 상태: DB 보안 변경·인덱스 생성과 운영 배포를 완료했다. 2026년 10월 7일 21:11(KST) 운영 주소의 HTTP 14개 항목, 보안 헤더, 배포 연결과 접근 보호 설정을 확인했다. 작업용 관리자·앱 DB 접속 파일은 삭제했다.**

## 운영 반영 결과

배포 소스는 커밋 `d51671bd7375579ce722b9ebdd0b6cc71f028bef`다. 사용하지 않는 옛 임시 파일 하나를 후보에서 제외한 뒤 재배포했으며, 최종 소스 목록의 600개 파일이 저장소 및 배포 폴더와 일치함을 별도 검토했다. 소스 변경 없이 문서에 운영 결과를 추가했다.

현재 운영 배포는 `dpl_9ZKL24XeA9TgEDNU76ddgXSzB9Fj`다. 관리자 접속으로 현재 DB를 확인하고 인덱스 2개를 온라인 생성한 뒤 0040을 한 트랜잭션에서 적용했다. 처음의 사후 검증은 관리자 역할의 `SET ROLE` 전환 제한으로 중단됐지만 DB 적용은 이미 완료된 상태였다. DDL을 재실행하거나 역할 권한을 넓히지 않고, 실제 앱 계정으로 직접 연결하여 검증을 마쳤다. 최초 실패 기록도 보관한다.

관리자 연결 파일 `neon-owner.env`, 앱 검증용 `runtime-verification.env`, 임시 Vercel 환경 파일 `production.env`를 삭제했다. 점검용 Vercel 우회 키는 0개이며 기존 배포 접근 보호 설정을 유지한다.

운영 HTTP 점검은 비로그인 요청과 쿠키 만료 응답을 확인했다. 이번 배포 후 브라우저에서 실제 Google 계정으로 새로 로그인하는 전 과정을 재검사하거나 실제 학생의 금융 거래를 실행한 것은 아니다. 인증 코드는 회귀 검사와 실제 DB 역할 검사로 확인했다.

## 적용 및 재현 절차

아래는 적용 순서와 복구 참고 사항이다. 이미 적용된 0040을 다시 실행하지 않는다.

1. 현재 Neon 연결이 이전 완료된 haeon0511 운영 프로젝트인지, 관리자·앱 역할 및 현재 인덱스 정의가 맞는지 확인한다. 옛 hwanit DB 연결 파일을 재사용하지 않는다.
2. 0039의 온라인 SQL로 두 인덱스를 트랜잭션 밖에서 `CONCURRENTLY` 생성한다. 존재하는 이름만으로 완료 처리하지 않고 정의·유효성·준비 상태를 확인한다.
3. 0040을 소유자 권한으로 한 트랜잭션에서 적용한다. `crs_app_runtime_haeon`에는 로그인 횟수 소비와 현재 세션 폐기 함수 두 개의 EXECUTE만 추가한다. 횟수 표에 직접 접근하는 권한은 부여하지 않는다.
4. 새 Vercel 배포를 `--prod --skip-domain`으로 생성한다. 현재 환경변수를 유지하며 관리자 DB 접속 정보는 업로드하지 않는다.
5. 후보 주소의 페이지·공개 상품·비로그인 접근 차단·보안 헤더를 확인한다. 임시 점검 접근키는 즉시 폐기한다.
6. DB 적용 및 후보 검증이 모두 완료된 경우에만 운영 주소를 승격하고 다시 확인한다. 작업용 관리자 연결 파일을 삭제한다.

0040과 함수 실행 권한이 빠진 상태로 새 인증 코드를 운영에 연결하면 비밀번호 로그인이 거절되거나 세션 로그아웃이 실패한다. 따라서 DB 확인 없이 운영 승격하지 않는다. 현재 사용 중단 약속을 새로 받거나 기존 서비스를 동결할 필요가 없는 추가 변경으로 준비했다.

## 남은 최적화와 유지 사항

- 과제 이벤트 전체 이력 읽기를 없애는 상태 요약 구조와 이력 페이지화는 후속 구조 작업이다. 이번 변경은 중복 조회와 불필요한 주기 조회를 줄인다.
- 과제 완료의 잠금 범위 축소는 동시성·선행 과제 변경 규칙을 함께 검증해야 하므로 이번 배포에서 잠금을 제거하지 않았다.
- 대형 관리자 컴포넌트 분리와 옛 Sheets 코드 제거는 별도 정리 작업으로 남긴다.
- 여러 학급을 동시에 쓰는 운영 용량을 새로 측정했다고 주장하지 않는다. 합계 집계는 조건에 맞는 전체 거래를 읽지만 응답·상품 항목·화면 목록은 페이지 크기로 제한한다.
- 사용자 보류 결정에 따라 매점의 학생 번호 공개 조회는 유지한다. 거래 취소의 음수 잔액 허용과 장부 기록 보존도 유지한다.
- 학급별 비밀번호 횟수 제한 때문에 다른 사용자가 횟수를 소진하면 교사도 잠시 기다릴 수 있다. Google 로그인은 계속 사용할 수 있다.
- 로그아웃은 현재 브라우저의 Google 쿠키를 제거한다. 이미 복제된 Google 쿠키까지 서버에서 폐기하는 별도 세션 구조를 이번 패치에 도입한 것은 아니다.
