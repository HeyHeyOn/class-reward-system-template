# CRS 패들렛 자동 확인 안정화 — 2026-10-12

이 문서는 `2026-10-12-crs-padlet-timeout-analysis.md`의 분석에 따른 수정·검증·배포 기록이다. 대상은 haeon0511 Vercel의 `crs-postgresql` 프로젝트와 `https://crs.hwanit.com`이다.

## 수정 내용

- **게시판마다 8초의 외부 읽기 시간**을 준다. 이전에는 교사 4초·학생 3초를 모든 게시판이 나누어 써서 뒤에 읽는 칭찬 게시판에 시간이 거의 남지 않았다.
- 한 실행은 최대 2개 게시판을 동시에 확인한다. 다음 실행은 한 번도 확인하지 않았거나 가장 오래 기다린 게시판을 우선한다. 35초가 지나면 새 작업을 시작하지 않고 다음 실행으로 넘긴다. 이는 새 작업 시작 한도이며 전체 작업의 절대 완료 시간 보장은 아니다.
- 자동·수동 확인은 DB의 동일한 게시판 확인 권한(60초 lease)을 사용한다. 외부 응답을 기다리는 동안 DB 트랜잭션을 열어 두지 않는다. 만료된 실행이 뒤늦게 도착해도 최신 실행의 결과·과제 단계·게시물 사용 기록을 덮지 못한다.
- HTTP 429를 받으면 같은 게시판의 자동 확인과 ‘지금 확인’은 최소 60초 동안 재요청하지 않는다. 게시판 주소 미리보기·연결 전 검증 조회는 이 주기적 동기화 gate와 별개다.
- 과제 목록은 저장된 결과를 먼저 표시한다. 인증된 요청에서 학급에 연결된 어댑터를 확정하고 Next.js `after()`로 확인을 이어간다. 실제 학급 API 경로의 실행 한도는 60초로 설정했다.
- 학생 은행의 연결 과제는 화면이 보이는 동안 20초마다, 또는 화면에 돌아왔을 때 갱신한다. 다른 화면·숨겨진 탭·로그아웃 상태에서는 요청하지 않는다. 이전 로그인 세션의 미완료 요청이 새 세션의 갱신을 막거나 덮지 않도록 했다.
- 오류 안내를 응답 시간 초과·권한·키·요청 제한 등으로 나누고 마지막 성공 시각, 확인 중 여부, 재시도 시각을 보여 준다. 진행 중이라고 이전 실패를 성공으로 표시하지 않는다.
- 외부 읽기는 응답 본문에도 시간·8MB 제한을 적용한다. 진단 로그에는 해시 처리한 게시판 식별자, 호출 경로, 제한 시간, 전체 처리 시간, HTTP 상태·바이트 수·결과만 남긴다. 학생 이름·게시물 본문·API 키·게시판 URL은 기록하지 않는다.

실행당 동시성 2개와 별개로 동일 게시판의 중복 실행은 DB가 차단한다. 여러 요청이 서로 다른 게시판을 맡으면 학급 전체에서는 동시에 2개를 넘을 수 있다.
