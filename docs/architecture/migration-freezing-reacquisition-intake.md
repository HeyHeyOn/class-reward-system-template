## Canonical HTTP contract

The composition's `canonicalPath` must be `/api/c/<canonical-slug>/migrations/<job-UUID>/freezing/reacquisition`. The canonical tenant must come from trusted directory resolution; dependency injection is not browser authority.

- `GET <path>/bootstrap`: current Google identity and current OWNER/ADMIN, actual `Sec-Fetch-Site: same-origin`, and absent or exact Origin. Returns a random synchronizer and an authenticated purpose/tenant/job/actor/original-session/digest/time-bound cookie. HttpOnly, Secure, SameSite=Strict, host-only, exact path, 60-second original lifetime. No challenge INSERT or outbound request.
- `POST <path>/challenge`: exact Origin, same-origin Fetch Metadata, JSON `{}`, original authenticated bootstrap cookie and `x-csrf-token`. Stores a new immutable SQL challenge and a **distinct confirmation synchronizer digest**. Returns the exact display and intent digest. Clears the cookie using the identical Path. Cookie clearing is not durable one-use enforcement.
- `POST <path>`: exact `{challengeId, display}` and confirmation `x-csrf-token`. SQL reservation and exact readback must acknowledge COMMIT before one bounded signed request to `/api/internal/migrations/freezing-reacquisition`. No transaction spans transport. No automatic retry.
- `GET <path>/<challengeId>`: exact `x-reacquisition-intent-digest`, original actor/session and current membership; returns archival facts only. Absent candidate means UNKNOWN, not proof of no external read. No sends, token exchange or capability mint.

All handler responses and canonical directory/method refusals are `no-store`. Canonical POST request bytes are capped at 8,192 with a five-second read deadline before directory SQL or JSON parsing, including absent/false Content-Length and unauthenticated streams. The internal handler retains its own cap. Cancellation occurs upon the first over-limit chunk; that incoming chunk exists transiently, but it is not retained in the bounded buffer. Non-success/redirect/oversized/expired transport responses fail closed. Unknown reservation or capture acknowledgements are conservatively UNKNOWN, never permission to resend.

## Bounded administrator diagnostic UI

`/c/<canonical-slug>/admin/migrations` retains the separate existing start action and adds `MigrationReacquisition` below it. The page requires current OWNER/ADMIN membership plus the ordinary identity session, with no compatibility-admin fallback. The shared manual job input accepts a literal canonical UUID for diagnostics; the existing start input behavior is unchanged. This is not job discovery or evidence that the entered job is FREEZING: the canonical server rechecks that state.

The Korean controls deliberately separate `진단 준비` (bootstrap GET), `진단 확인 정보 받기` (challenge POST), checkbox plus `진단용 읽기 실행` (confirmation POST), and `진단 보관 상태 조회` (archival GET). Mount, rendering, timers and visibility effects never issue requests. There is no Google popup, polling, automatic confirmation, retry or remint. Diagnostic candidates remain `NONAUTHORITY`, `NOT_PROVEN`, `finalImportEligible: false`; this does not replace the separate fresh final-purpose consent/acquisition.

The UI sends exact canonical same-origin paths, exact `{}` and `{challengeId, display}` bodies, the appropriate distinct synchronizer header for each POST, and the original intent-digest header for status. Cookies, Origin and Fetch Metadata remain browser-managed (`credentials: same-origin`). No token is reflected in the DOM, copied into URLs, or written to local/session storage. The exact server display is rendered unchanged, including bounded server actor/session-binding provenance; those display hashes are not credentials or reconstructed authority. The bootstrap response has only scope/token/expiry, not tenant/job fields: its HTTP path plus server-verified HttpOnly cookie supplies that binding, not an invented client field.

Responses are capped at 16,384 retained streaming bytes before JSON parsing, with a 20-second request/body deadline, strict JSON content type, no redirects and strict bounded shapes/scalars. Approval validates canonical UUIDs, tenant/job/challenge equality, purpose/action/status/version, digest formats, flags, exact 60-second lifetime and expiry before enabling. Candidate/status results additionally match the original challenge, intent and execution digest and exact audit identifier. Client presentation checks are not cryptographic or fresh membership authority; the canonical server owns those checks.

Synchronous refs consume one-shot actions before awaiting transport, independent of React batching or repeated mouse/keyboard clicks. Deadlines and dispatch/postresponse expiry checks fail closed. Hidden/pagehide invalidates in-flight generations and discards approval, but retains the already received non-authorizing archival reference within the same job/tenant/login context. Untouched idle controls are not consumed by tab navigation. Job changes and keyed tenant/login changes (subject, email, issuedAt) clear everything; unmount aborts and invalidates outstanding requests. A cookie changed outside this page is revalidated by the server on the next explicit request, not discovered by polling. A challenge response lost before its reference arrives cannot be recovered by inventing identifiers.

Any confirmation failure or ambiguity is terminal UNKNOWN: it may have executed, and no resend button is offered for that attempt. The original reference permits manual archival reads only; missing archival evidence also remains UNKNOWN. The UI warns that refresh/closing can lose its memory-only reference. Status cannot restore approval or final-import eligibility.
