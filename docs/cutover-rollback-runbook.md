# Cutover STOP / ABORT / rollback — operator minimum

> **2026-10-07 복구 기준:** 운영 권위는 이전 완료된 새 Neon DB에 있다. 과제 장부 도입 전 코드나 옛 DB에 연결된 배포를 그대로 승격하지 않는다. 현재 DB와 장부 데이터를 지원하는 수정 배포를 우선한다. 옛 DB 쓰기 재개만으로 복구할 수 없으며 전환 이후 기록의 대조·이전이 필요하다. 아래 과거 Task19–24 복구 요구와 당시 미구현 상태는 역사적 범위다. 최신 운영 상태는 [README](../README.md), 계정·배포 상세는 비공개 단일 진행 기록을 확인한다.

Status: procedure boundary, **not permission to operate**. No command or public API for cutover/rollback is asserted here. Production freeze, writer disable/re-enable, grant revocation, authority switch, export application and deployment are **unexecutable without separate explicit approval and a verified implementation**. The source Sheets/Redis stay authoritative until a verified write exclusion and a completed authority transition; a local candidate, receipt row or PostgreSQL commit alone does not prove that people editing Sheets or old deployments/Redis writers have stopped. [Plan: Task 17–19](plans/2026-08-28-postgres-multitenant-migration.md#L225-L247); [receipt storage boundary](../src/server/db/migrations/0013_migration_authority_storage.sql#L1-L3).

## STOP before activation

- [ ] Identify the exact tenant, migration job, original Sheet/source, expected status/version/fingerprint, and the authorized operator from independently retrieved state. Do not infer authority from caller-supplied proof strings or local staging. [Abort binding and authentication](../src/server/migration/cutover.ts#L11-L68).
- [ ] If the source changed, reconciliation is incomplete, approval/consent is missing, or exclusion of **both** human Sheet editors and every old deployment/Redis writer is not independently verified and still maintained, **STOP**. Do not enter/continue cutover, activate PostgreSQL claims, or allow two active writers. Freeze proof is an external operational gap, not something a database transaction can certify. [Plan: reconciliation/freeze](plans/2026-08-28-postgres-multitenant-migration.md#L225-L247).
- [ ] Preserve original snapshots, immutable audit, source data and diagnostic evidence. Record the unresolved owner, writer paths, observed mismatch and time; do not mark the cutover successful. A failed fence is **not** repaired by setting a status flag. [Plan: freeze and final delta](plans/2026-08-28-postgres-multitenant-migration.md#L231-L247).

## Supported internal ABORT boundary (not an operator endpoint)

`createLegacyCutoverAbortService` is an internal server composition function, **not a documented CLI/API or an instruction to invoke it here**. With a canonical route-resolved tenant and authenticated Google subject, it accepts an exact bound intent (job, current status, state version, source fingerprint). The job may be `DISCOVERED`, `VALIDATED`, `IMPORTING`, `RECONCILING`, `READY`, `FREEZING`, or `FINAL_IMPORT`; **not** `ACTIVE`, `FAILED`, or `ABORTED`. The tenant lifecycle must be `DRAFT`, `IMPORTING`, or `READY`, and the current subject must be a tenant `OWNER`/`ADMIN`. Any stale binding, membership failure or unsupported state refuses the transaction. [Intent and status checks](../src/server/migration/cutover.ts#L7-L24); [locks and membership](../src/server/migration/cutover.ts#L45-L68); [DDL transitions](../src/server/db/migrations/0003_operations_migrations.sql#L150-L168).

On success the single tenant transaction appends and reads back a redacted `MIGRATION_CUTOVER_ABORTED` audit event, conditionally changes the job to `ABORTED`, increments `state_version`, sets `completed_at`, and reads the state back. It returns `externalCleanup: NOT_PERFORMED`: it **does not** release or prove an external writer fence, reverse a data import, switch authority, delete grants, or undo a deployment. `ABORTED` is terminal in the current transition trigger; do not claim automatic resume/retry. [Implementation](../src/server/migration/cutover.ts#L70-L99); [state machine](../src/server/db/migrations/0003_operations_migrations.sql#L150-L168).

## After any activation/commit

- [ ] STOP the unsafe writer path and preserve evidence; do **not** point users back at an old Sheet URL or re-enable the old writer. An application-version rollback must keep PostgreSQL authoritative. [Plan: rollback distinction](plans/2026-08-28-postgres-multitenant-migration.md#L257-L263).
- [ ] Treat recovery as forward repair of the authoritative PostgreSQL state. A storage move back to Sheets would require a **separately approved and implemented** DB-write freeze, export/apply of every post-cutover delta, full balances/stock/ledger/tasks/claims reconciliation, atomic authority change and *then* legacy-writer re-enable. This is **not implemented by the ABORT service**, and this document supplies no executable steps for it. [Plan: Task 21](plans/2026-08-28-postgres-multitenant-migration.md#L257-L263); [ABORT limitations](../src/server/migration/cutover.ts#L37-L43).

Before any live procedure, require an approved operator path, validated exclusion evidence, completed reconciliation/export and an isolated rehearsal; the plan separately requires preview-DB transaction rehearsal and controlled rollout. [Plan: Task 23–24](plans/2026-08-28-postgres-multitenant-migration.md#L273-L296).
