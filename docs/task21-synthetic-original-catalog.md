# Task21 synthetic ORIGINAL catalog enrollment and transaction fence

> **과거 실험 기록:** Task1–24 계획에 속한 당시의 합성 검증·복구 실험이다. 현행 A–F의 실행 순서나 현재 운영 완료율을 나타내지 않는다. 현재 상태는 [README](../README.md)를 따른다.

Scope: source-owned synthetic sealed export to a FRESH launcher-owned disposable PostgreSQL 17. This is a catalog prerequisite, NOT a successor grant. ColdLease, execution pins, WeakMaps, quarantine, original replay/settlement and preparation admission remain separate.

## Enrollment and trust root

The source enrolls each allowed private table in the transaction that creates it, before its first INSERT. Terminal singleton baselines also bind the exact intended canonical payload/digest; the restore lease binds database, system, owner, tenant and job; journals bind chain, parent, source and physical database identity. Existing admission independently checks coordinator/terminal/seal/chain/owner and original execution authority. Read/retry never enrolls or adopts missing evidence.

The independent store is `.synthetic-original-catalog/<native-system-id>-<database-oid>-<fixed-private-table>/<full-xid>.json`, under the frozen fixture working directory. Directories require owner UID and mode 0700, files require mode 0400, regular single-link files, bounded size and O_NOFOLLOW. Source publication is exclusive-create and fsynced before SQL COMMIT. It is not stored in, imported from, or recreated by archive SQL. No current catalog is silently blessed on read. A committed original cannot be overwritten or re-enrolled, even after DROP/recreate. Same-UID filesystem compromise and container host/binary/storage compromise are outside this controlled fixture boundary; mode 0400 is not represented as hardware immutability.

A native creation xmin and empty table are required at enrollment. Subtransaction/savepoint creation and xid wraparound adoption are intentionally unsupported. Full-xid records are append-only. A transaction that rolled back leaves an orphan record; native pg_xact_status must report ABORTED before it may be ignored. A retry can append a new creation xid without deleting old evidence. Exactly one committed/current original is accepted. Unknown/too-old transaction status, another live enrollment, duplicate originals, a missing/malformed baseline or catalog drift fails closed. The commit-before/after process-kill envelope is not a new successor or host-loss recovery proof.

## Native fence and catalog coverage

PostgreSQL 17 READ COMMITTED, non-read-only, explicit transaction, postgres session/current user, superuser, origin replication, allow_system_table_mods OFF and the exact ordinary default search_path are required. Schema-qualified pg_catalog.current_setting bootstraps path validation before resolving other functions/operators. All native heap catalogs in pg_catalog (including shared pg_authid/pg_auth_members and database catalogs) receive SHARE locks retained natively to the transaction end. This includes pg_proc, namespace, class, attribute, type, trigger, constraint, index, policy, role and ACL catalogs. The existing private relation SHARE lock and exact immutable-function/trigger checks remain. Public row locks and existing public guard/sequence/base checks remain; source-controlled creation and protected DML share the transaction fence. This is deliberately coarse, synthetic-only and not a production locking design.

A catalog-lock/privilege/timeout failure has no relation-only fallback and performs no protected DML. No advisory cooperation, event-trigger opt-out, server configuration relaxation, altered writer fence or ACTIVE state is used. Competing native SQL replacement/ALTER/DROP/ACL DDL must wait or fail lock_timeout. The fixture capability probe records allow_system_table_mods OFF; no server flags are changed.

Each per-table ORIGINAL includes native OIDs and semantic catalog fields for schema owner/ACL; table and indexes (including table ACL/RLS/options); columns/types/defaults; constraints; triggers including conditions/arguments; rules; policies; index definitions; all functions in that private schema including source/configuration/ACL/owner; languages and their handler/inline/validator function rows; global event triggers; role privilege attributes and membership (NOT password fields); database owner/ACL; role/database settings and default ACL; inheritance. Vacuum/planner counters and physical storage bookkeeping are explicitly excluded (relpages, reltuples, relallvisible, relfrozenxid, relminmxid, relfilenode, reltoastrelid). This is not an independent raw baseline for all public/system objects or external C libraries. Existing archive public guard and sequence validation remains its own contract.

The baseline is semantic plus native object identity, not MVCC tuple identity. Restoring a function body with CREATE OR REPLACE retains its OID; dropping/recreating a trigger does not restore the ORIGINAL OID. Destructive mutation tests therefore use native rollback or end with denial, not a repair/re-enrollment shortcut. Frozen historical tests/evidence are unchanged.

## Evidence contract

New dispatch native RED observes admission with a lease SHARE lock, connection B committing function replacement before connection A's protected UPDATE, and exact rollback reconciliation. A distinct capability probe proves pg_proc SHARE excludes replacement with normal fixture privileges. GREEN records native backend IDs/blocking PID lists, waiting DDL, original COMMIT and ROLLBACK release, post-release DDL commit, original baseline byte preservation, and protected UPDATE refusal. Negative tests cover ACL/owner, columns, constraints, function body/configuration/security mode and trigger condition/enabled state. Reduced privilege/autocommit/stale isolation/missing baseline/aborted enrollment are fail-closed controls. Exact private/public row, sequence and catalog witnesses accompany the tests; execution/authority witnesses remain distinct.
